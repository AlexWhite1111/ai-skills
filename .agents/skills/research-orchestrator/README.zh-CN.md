# Research Orchestrator Skill

这是一个给 AI 使用的科研调度 skill。它不是把某个数学 Prompt 原样扩大，而是把其中真正有价值的调度思想抽出来，做成一套可迁移到数学证明、物理建模、因果研究、工程架构和复杂排障的协议。

一句话概括：

> 先隔离事实、假设、候选解释和验证，再让不同机制的路线独立生长；把“换个名字的难题”判为零进展；候选结果必须经过专门找漏洞的审计，最后只按证据闭合程度报告。

## 与金山木原 Prompt 的关系

保留了这些核心思想：

- 动态多路线搜索，而不是固定分工；
- 早期信息隔离，防止所有 Agent 跟随领先路线；
- 按思想机制建立路线家族；
- 将卡在同等难度引理上的路线标为 blocked；
- 延迟交叉传播；
- 使用敌对 Agent 找循环、漏条件和反例；
- 不把漂亮归约、有限计算和模糊乐观当作完成。

本 skill 另外补上了原 Prompt 不负责解决的部分：

- 将“假定正面证明存在”降为搜索先验，不当作真值；
- 默认保留证明与证伪双轨；
- 明确分离观察、假设、假说和验证；
- 给出有限预算和诚实停止规则；
- 区分同模型自检、独立实现、形式验证、专家审查等验证等级；
- 支持经验科学、因果问题、工程设计和调试，而不只支持定理证明；
- 先压缩主干，再展开路线，避免研究报告变成枝叶仓库。

## 目录

- `SKILL.md`：AI 的主操作协议。
- `agents/openai.yaml`：skill 的显示信息和默认调用语句。
- `references/protocol.md`：完整调度循环。
- `references/state-model.md`：研究状态、路线、缺口和攻击的数据模型。
- `references/agent-briefs.md`：探索者、证伪者、形式化者、审计者等动态角色模板。
- `references/audit.md`：敌对审计协议。
- `references/evals.md`：防止 skill 退化的测试集。
- `assets/research-ledger-template.md`：长任务使用的研究账本模板。

## 在 Codex 中调用

```text
Use $research-orchestrator to investigate this problem.
```

中文也可以：

```text
使用 $research-orchestrator 研究这个问题。先压缩目标，隔离观察、假设、假说和验证；建立真正不同的路线家族；不要把等价改写当进展；候选结论必须经过敌对审计。
```

## 设计边界

它不会自动让一个弱模型变成数学家，也不能把同一个模型的多次赞同伪装成独立同行评审。它解决的是另一层问题：让现有推理能力不那么容易被羊群效应、漂亮废话、隐藏假设和假进度浪费。
